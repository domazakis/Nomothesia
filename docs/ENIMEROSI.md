# Πώς ενημερώνεις το corpus

Ο σκοπός αυτού του αρχείου είναι να μπορείς να ενημερώσεις τη νομοθεσία χωρίς να
θυμάσαι τίποτα από τον κώδικα.

## Η σύντομη εκδοχή

```bash
nomothesia fetch
```

Αυτό είναι όλο. Η εντολή κατεβάζει ό,τι έχει αλλάξει, ξαναχτίζει τα κείμενα και
σου λέει στο τέλος τι κινήθηκε. Μετά:

```bash
git add corpus/ && git commit -m "Ενημέρωση corpus" && git push
```

## Τι σημαίνει η έξοδος

```
→ kok-5209-2025 (Ν. 5209/2025)
  ✓ 132 άρθρα, 418 παράγραφοι

Αλλαγές:
  • ya-50984-2013: τροποποιημένο
```

- **νέο** — μπήκε για πρώτη φορά στο corpus.
- **τροποποιημένο** — το κείμενο άλλαξε. Δες το `git diff` για το τι ακριβώς.
- **απόν** — υπήρχε στο corpus αλλά έφυγε από το μητρώο.

Τα αμετάβλητα δεν αναφέρονται· δεν είναι είδηση.

## Το πρόβλημα του δικτύου σε cloud συνεδρίες

Αν δεις αυτό:

```
✗ το δίκτυο απέρριψε τη σύνδεση προς www.et.gr (403 Forbidden).
```

δεν φταίει ο κώδικας. Τρέχεις μέσα σε cloud συνεδρία της οποίας η πολιτική
δικτύου δεν επιτρέπει το `et.gr`. Τρεις λύσεις.

### Λύση Α — τρέξε το GitHub Action

Ο ευκολότερος δρόμος, γιατί δεν αλλάζεις τίποτα πουθενά. Οι runners της GitHub
δεν έχουν αυτόν τον φράχτη: το ίδιο workflow που τρέχει κάθε Δευτέρα τρέχει και
χειροκίνητα.

Στο **Actions** → **Έλεγχος αλλαγών νομοθεσίας** → **Run workflow**.

Κατεβάζει τα κείμενα από τους runners και ανοίγει pull request με το corpus.
Χρήσιμο και για την πρώτη συμπλήρωση, όχι μόνο για τις ενημερώσεις.

> Αν το βήμα «Άνοιγμα pull request» αποτύχει με `403`, λείπει μία ρύθμιση του
> repository: **Settings → Actions → General → Workflow permissions →
> «Allow GitHub Actions to create and approve pull requests»**.

### Λύση Β — τρέξε την εντολή τοπικά

Στον δικό σου υπολογιστή δεν υπάρχει φράχτης:

```bash
git clone https://github.com/domazakis/Nomothesia
cd Nomothesia
uv venv && uv pip install -e .
nomothesia fetch
```

### Λύση Γ — επίτρεψε τα domains στο cloud environment

1. Στο [claude.ai/code](https://claude.ai/code), πάτα το **εικονίδιο σύννεφου**
   με το όνομα του environment, στη σειρά πάνω από το πλαίσιο μηνύματος.
   Δεν υπάρχει σελίδα ρυθμίσεων με δικό της URL — μόνο από εκεί.
2. Κάνε hover στο environment και πάτα το **γρανάζι** που εμφανίζεται δεξιά.
3. Στο **Network access** διάλεξε **Custom**.
4. Στο **Allowed domains** βάλε ένα ανά γραμμή:

   ```
   www.et.gr
   et.gr
   search.et.gr
   *.et.gr
   www.kodiko.gr
   eur-lex.europa.eu
   www.e-nomothesia.gr
   diavgeia.gov.gr
   www.gov.gr
   ```

5. **Τσέκαρε το «Also include default list of common package managers».**
   Αν το αφήσεις κενό, χάνεται η πρόσβαση σε PyPI και GitHub και δεν
   εγκαθίστανται καν οι βιβλιοθήκες.
6. Αποθήκευσε και **άνοιξε νέα συνεδρία** — η τρέχουσα κρατά την παλιά πολιτική.

## Όταν βγει καινούριος νόμος

Το `fetch` ενημερώνει ό,τι υπάρχει ήδη στο μητρώο. Ένα **νέο** νομοθέτημα πρέπει
πρώτα να προστεθεί στο `sources/registry.yaml`:

```yaml
  - id: nomos-XXXX-2027
    titlos: Ο τίτλος όπως ακριβώς είναι στο ΦΕΚ
    typos: nomos            # ή pd, ya, kya, kanonismos_ee, odigia_ee
    arithmos: "XXXX"
    etos: 2027
    fek: {teuxos: A, arithmos: 123, imerominia: 2027-03-15}
    thematiki: kok          # μία από τις υπάρχουσες θεματικές
    proteraiotita: 1        # 1=πυρήνας, 2=σημαντικό, 3=περιφερειακό
    katastasi: isxyon
    epalithevmeno: false
    perigrafi: >-
      Τι ρυθμίζει, σε δυο-τρεις γραμμές.
    piges:
      - {typos: fek_pdf, url: "https://www.et.gr/api/DownloadFeksApi/?fek_pdf=20270100123"}
```

Το `fek_pdf` URL φτιάχνεται μηχανικά: **έτος** (4 ψηφία) + **τεύχος**
(`01` για Α΄, `02` για Β΄) + **αριθμός ΦΕΚ** (5 ψηφία με μηδενικά μπροστά).
Π.χ. ΦΕΚ Α΄123/2027 → `20270100123`.

Μετά:

```bash
nomothesia validate            # ελέγχει ότι δεν έσπασε τίποτα
nomothesia fetch --id nomos-XXXX-2027
```

Αν ο νέος νόμος **αντικαθιστά** παλιό, μη σβήσεις τον παλιό. Άλλαξε την
`katastasi` του σε `istoriko` και δήλωσε τη σχέση:

```yaml
    scheseis:
      antikathista: [to-palio-id]
```

Έτσι ο agent θα ξέρει ότι υπάρχει και τι το αντικατέστησε — κρίσιμο για
ερωτήσεις που αφορούν παλαιότερα συμβάντα.

## Αυτόματος έλεγχος

Το GitHub Action `.github/workflows/update.yml` τρέχει κάθε Δευτέρα, ελέγχει τις
πηγές και ανοίγει pull request **μόνο** αν κάτι όντως άλλαξε.

Το χρώμα του run λέει τα υπόλοιπα:

| Run | PR | Τι σημαίνει |
| --- | --- | --- |
| ✅ πράσινο | ήρθε | Άλλαξε η νομοθεσία. Δες το diff. |
| ✅ πράσινο | κανένα | Όλες οι πηγές απάντησαν και δεν άλλαξε τίποτα. Ησυχία. |
| ❌ κόκκινο | — | Κάποια πηγή δεν κατέβηκε. Αν ήρθε και PR, περιέχει μόνο όσα πέτυχαν. |

Η διάκριση έχει σημασία: **σιωπή χωρίς κόκκινο σημαίνει ότι ο νόμος όντως δεν
άλλαξε**, όχι ότι δεν κατάφερε κανείς να τον δει. Σε κάθε run, η καρτέλα
**Summary** δείχνει ποιες πηγές απάντησαν και ολόκληρο το log της λήψης.

## Όταν κάτι αποτύχει

| Μήνυμα | Τι σημαίνει |
| --- | --- |
| `δεν εντοπίστηκε κανένα άρθρο` | Άλλαξε η διάταξη της πηγής ή το URL δείχνει αλλού. Άνοιξε το URL στον browser. |
| `το PDF δεν έχει επίπεδο κειμένου` | Σαρωμένο έγγραφο. Χρειάζεται OCR: `uv pip install -e '.[ocr]'`. |
| `τα στοιχεία ΦΕΚ δεν εντοπίστηκαν` | Πιθανώς λάθος `fek_pdf` id. Κατέβασε το URL χειροκίνητα και δες ποιο ΦΕΚ είναι. |
| `άκυρο μητρώο` | Συντακτικό λάθος στο `registry.yaml`. Το μήνυμα δείχνει το πεδίο. |
